# Отчёт: доказательный RAG по ТФКП

## 1. Подготовка данных

Готовые файлы корпуса и вопросов не были предоставлены, поэтому они подготовлены в рамках проекта. Скрипт `extract_native_markdown.py` извлекает Markdown из учебника. `extract_text.py` преобразует его в `corpus.jsonl`, содержащий текстовые фрагменты, формулы и исходные идентификаторы `block_id`. Скрипт `extract_questions_dev.py` использует `tfkp_15_qa.md` и подготовленный корпус для формирования `dev_questions.jsonl` и `dev_gold.jsonl`, включая разметку источников.

Для собственных проверок также подготовлены `own_questions.jsonl` и `own_gold.jsonl`. В проект включены скрипты подготовки данных, корпус, ответы, трассировки и результаты экспериментов.

## 2. Архитектура и параметры

Используемая генеративная модель — **`Qwen/Qwen3.5-4B`**. Запуск модели выполнялся в Google Colab на бесплатном GPU NVIDIA T4.

Для извлечения свидетельств используется BM25 (`BM25Okapi`) с параметрами \(k_1=1.5\) и \(b=0.75\). Токенизация приводит текст к нижнему регистру, учитывает математические символы, допускает токены длиной от одного символа и использует настройки для русского языка со стеммингом.

Корпус содержит 968 документов, среднее число токенов на документ — 58,228. Время построения индекса составило 0,087 секунды, пиковое использование RAM — 44,93 MB, размер индекса — 1 111 077 байт (около 1,06 MB).

В стандартной конфигурации извлекается до пяти фрагментов (`top_k = 5`). Параметры генерации: `temperature = 0.0`, `max_tokens = 1024`; тайм-аут — 180 секунд.

## 3. Ответ, ссылки и отказ


Режим `no_context` получает вопрос и варианты без фрагментов корпуса и служит контрольным экспериментом. `rag_single` выполняет BM25-поиск и один вызов LLM без повторной попытки. В `final` добавлена проверка ссылок и разрешена ровно одна дополнительная попытка LLM при ошибке валидации, связанной с цитатами (например, если указанный `block_id` отсутствует среди найденных фрагментов или ответ не содержит обязательных цитат). Повтор не запускается для любой ошибки подряд и не является фиксированным вторым шагом. Если повторная попытка тоже не проходит проверку, система возвращает отказ с диагностической причиной.

## 4. Эксперименты

Проведены пять экспериментов:

- `no_context` — генерация без извлечённого контекста;
- `rag_single` — BM25 и один вызов LLM;
- `final` — основная RAG-система;
- `ablation_no_rerank` — отключение ранжирования фрагментов по BM25;
- `ablation_top1` — использование только одного извлечённого фрагмента.

**Поскольку baseline-конфигурация не была предоставлена в задании, в качестве базовой конфигурации (baseline) была выбрана rag_single.**

## 5. Анализ абляций

**Отключение ранжирования (`ablation_no_rerank`).** Итоговый Q снижается с 0,7346 до 0,4800. Особенно заметно падение на коротких вычислениях — с 0,33 до 0,00 — и на вопросах об условиях теорем — с 0,74 до 0,32. Это указывает на важность релевантности и порядка извлечённых фрагментов.

**Ограничение контекста одним фрагментом (`ablation_top1`).** Итоговый Q снижается до 0,6533. Среднее число входных токенов уменьшается с 1285,8 до 564,9, а средняя стоимость — с 2009,5 до 1205,7. Меньший контекст снижает затраты, но ухудшает качество.

**Сравнение с генерацией без контекста.** `final` превосходит `no_context` по `answer_accuracy` (0,7440 против 0,5733) и по Q из `evaluate.py` (0,7346 против 0,5867). Это указывает на пользу извлечения свидетельств. При этом `final` и `rag_single` имеют одинаковые метрики качества и среднее число вызовов LLM 1,00; по этим агрегированным результатам нельзя утверждать, что повторные попытки дали измеримый прирост качества в данном прогоне.

## 6. Анализ ошибок с `final`

### Ошибка 1 — q_002: ошибочный отказ от ответа

**Вопрос:** Пусть f непрерывно дифференцируема как функция двух вещественных переменных в открытой области D. Какие условия, выполняющиеся всюду в D, эквивалентны голоморфности f?

**Правильный ответ:** A, C.

**Ответ модели:** "отказ"

**Обоснование модели:** 
> В предоставленных фрагментах отсутствуют теоретические сведения о критериях голоморфности функции двух вещественных переменных (например, формула Коши-Римана в комплексной форме или условие на частные производные). Фрагменты содержат примеры вычисления интегралов, задачи Дирихле и разложения в ряды, но не отвечают на вопрос о необходимых и достаточных условиях голоморфности для произвольной дифференцируемой функции.

**Анализ ошибки:**  Ошибка связана с тем, что BM25 не извлёк достаточно релевантные фрагменты для данного критерия. В trace были найдены блоки `b0000454`, `b0000403`, `b0000466`, `b0000414`, `b0000832`. Для улучшения результата необходимо повысить качество retrieval для вопросов об условиях Коши—Римана в комплексной форме.

### Ошибка 2 — q_007: ошибочный отказ при вычислении интеграла

**Вопрос:** Окружность \(\gamma:|z|=1\) обходится один раз против часовой стрелки. Вычислите \(\int_\gamma e^z/z^3\,dz\).

**Правильный ответ:** C.

**Ответ модели:** "отказ"

**Обоснование модели:**

> Для вычисления интеграла необходимо найти вычет функции \(f(z)=e^z/z^3\) в точке \(z=0\). Фрагменты предоставляют примеры вычислений интегралов с вычетами (b0000414) и теоремы о голоморфности (b0000161), но не содержат конкретных вычислений для функции \(e^z/z^3\) или значения ее вычета, что делает ответ невозможным без внешних знаний.



**Анализ ошибки:** В trace были найдены блоки `b0000403`, `b0000466`, `b0000263`, `b0000161`, `b0000414`. Вероятная причина ошибки — найденный контекст не позволил модели связать интеграл с формулой Коши для производных. Для улучшения системы следует повысить качество поиска фрагментов, содержащих формулы интегралов с производными, и обеспечить извлечение достаточного контекста для коротких вычислительных задач.

### Ошибка 3 — q_010: неверный набор вариантов ответа

**Вопрос:** Функция f голоморфна в окрестности 0, причём \(f(0)=2\), \(f'(0)=-1\), \(f''(0)=6\). В разложении \(f(z)=\sum_{n=0}^\infty c_n z^n\) какие равенства верны?

**Правильный ответ:** A, B, D.

**Ответ модели:**
- `answer_ids`: `["A", "B"]`
- `abstain`: `false`
- `citations`: `["b0000454", "b0000403", "b0000127", "b0000161", "b0000198"]`

**Обоснование модели:**

> По определению коэффициентов ряда Тейлора c_n = f^(n)(0)/n!. c_0 = f(0) = 2, c_1 = f'(0) = -1, c_2 = f''(0)/2! = 6/2 = 3. Варианты A и B верны, C неверен (6!=3), D неверен (3!=3).

**Анализ ошибки:** Модель правильно вычислила коэффициенты \(c_0\) и \(c_1\), а также получила \(c_2=3\). Однако она не включила вариант D в итоговый список, несмотря на то что собственное обоснование модели подтверждает равенство \(c_2=3\).

По формуле коэффициентов ряда Тейлора

\[
c_n=\frac{f^{(n)}(0)}{n!}.
\]

Следовательно,

\[
c_0=f(0)=2,\qquad c_1=f'(0)=-1,
\]

\[
c_2=\frac{f''(0)}{2!}
=\frac{6}{2}=3.
\]

Таким образом, верны варианты A, B и D, а вариант C неверен.

В trace были найдены блоки `b0000454`, `b0000403`, `b0000127`, `b0000161`, `b0000198`. Ошибка связана не столько с вычислением, сколько с согласованием математического вывода с идентификаторами вариантов ответа.
## 7. Ограничения и воспроизводимость

Набор оценки включает 15 вопросов, поэтому результаты следует рассматривать как оценку на небольшом тестовом наборе. Для воспроизведения необходимо сохранить корпус, разметку, конфигурации, код, ответы и трассировки. Индекс BM25 можно перестроить из корпуса; веса и кэш модели не следует включать в репозиторий.

Параметры индексирования: 968 документов, 0,087 секунды построения, 44,93 MB пиковой RAM и размер индекса около 1,06 MB. Генерация выполнялась в Google Colab на бесплатном GPU NVIDIA T4.
